# ankush-site-worker

A small Cloudflare Worker (no dependencies, no build step) that backs three
features of [ankush.one](https://ankush.one):

- **Link proxy** — lets the desktop open external links inside an embedded
  window even when the target site forbids framing (`X-Frame-Options`,
  CSP `frame-ancestors`), and shows a Wayback Machine fallback for dead sites.
- **GIF search** — forwards the IRC app's GIF search to Klipy so the API key
  lives in a Worker secret instead of in the page's JavaScript.
- **MCP server** — a read-only [Model Context Protocol](https://modelcontextprotocol.io)
  endpoint at `/mcp`, so AI agents can search the site and read its pages
  through tools instead of scraping the desktop (`src/mcp.js`). The same
  search is also served as plain markdown at `/search?q=` for agents that can
  only fetch URLs.

The site works without it: while `params.linkProxy` in `hugo.toml` is empty the
feature is off, external links behave as they always have, and nothing
advertises the MCP server.

## Deploy

```sh
cd workers/site-worker
npx wrangler login                      # once
npx wrangler deploy                     # prints https://ankush-site-worker.<account>.workers.dev
npx wrangler secret put KLIPY_API_KEY   # paste the Klipy key (optional: only /gif needs it)
```

Then set the Worker URL (no trailing slash) in `hugo.toml` and redeploy the site:

```toml
[params]
  linkProxy = "https://ankush-site-worker.<account>.workers.dev"
```

Check it: `curl https://ankush-site-worker.<account>.workers.dev/health` prints `ok`.

With `linkProxy` set, the site build also advertises the MCP server: a line in
the "For agents" section of `/llms.txt` and `/llms-full.txt`
(`layouts/partials/agents/endpoints.md`) and a server card at
`https://ankush.one/.well-known/mcp.json` pointing at `<linkProxy>/mcp`.
The same llms.txt block also lists `<linkProxy>/search?q=`.

**Use the default `*.workers.dev` hostname, not a subdomain of ankush.one.**
Proxied pages run their own scripts on the Worker's origin. On a separate
registrable domain they can never read or set `ankush.one` cookies or storage.

Once the Worker serves `/gif`, rotate the Klipy key: the old one is committed in
`assets/js/irc-chat.js` history and should be treated as public.

## Configuration (`wrangler.toml` `[vars]`)

| Name | Default | Purpose |
| --- | --- | --- |
| `SITE_ORIGINS` | `https://ankush.one` | Origins allowed to embed the proxy and call `/check` and `/gif`. The first one is the "home" site named on the worker's own pages. Add `http://localhost:1313` only on a local `wrangler dev` (see Local development), never in the deployed config. |
| `ALLOWLIST_URL` | `https://ankush.one/external-hosts.json` | `{"hosts": ["github.com", ...]}`, generated by the Hugo build from every external link on the site. |
| `EXTRA_HOSTS` | *(empty)* | Comma-separated hosts allowed in addition to the generated list. |
| `KLIPY_API_KEY` | *(secret)* | Klipy key for `/gif/*`. Without it those routes answer `503`. |
| `SITE_URL` | `https://ankush.one` | Site the MCP server reads. Falls back to the first of `SITE_ORIGINS`. |
| `MCP_RATE_LIMITER` | 60 per minute | `[[ratelimits]]` binding, not a var: per-IP limit for `POST /mcp` and, under separate keys, for `GET /search` and `/gif/*`, counted per Cloudflare location. The code skips the check when the binding is absent, so the block can be deleted from `wrangler.toml` if a deploy ever rejects it. |

A listed host also allows its subdomains (`github.com` covers `gist.github.com`);
a leading `www.` is ignored. `web.archive.org` is always allowed.

## Routes

### `GET /?url=<absolute http(s) url>` — the proxy

Meant to be the `src` of an iframe on the site. In order:

1. **Refuse** anything that fails the gates below.
2. **Not on the allowlist** → a small page with an "Open in new tab" link
   (the visitor probably clicked onward inside a proxied page). Redirects are
   followed by hand, at most 8, and every hop is vetted like the first url
   *before* it is requested: a redirect to a host that is not on the allowlist
   gets this same page and is never fetched.
3. **Dead** (connection/DNS failure, timeout, or `404`/`410`/`5xx`) → a page
   saying the site or page is no longer online, with a button to the closest
   Wayback Machine snapshot when one exists and a link to try the original in a
   new tab. Snapshot pages may be framed, so the button navigates the window
   straight to the snapshot.
4. **Walled** (any other `4xx`, non-standard codes such as LinkedIn's `999`, a
   Cloudflare challenge, or a redirect to an address the Worker refuses) →
   "this site cannot be shown in a window" with a new-tab link. These sites are
   online; they just refuse the Worker.
5. **Frameable** (no `X-Frame-Options`, no blocking `frame-ancestors`) → `302`
   to the real url, so it runs natively with full fidelity.
6. **http-only page** while the Worker is on https → the "Open in new tab"
   page. Proxied, its stylesheets, scripts and images would all be blocked as
   mixed content.
7. **Otherwise proxied.** For `text/html` the Worker streams the page through
   `HTMLRewriter`: it injects `<base href="<final url>">` so every subresource
   loads straight from the origin, routes GET forms and meta refreshes back
   through `/?url=`, drops in-page CSP / `X-Frame-Options` / referrer metas,
   and adds a ~1 KB script that sends in-frame link clicks through the proxy
   and keeps `#fragment` links on the page. Links are not rewritten in the
   markup (see the budget section), so with scripts disabled, or when a page
   stops the click event from bubbling, a link navigates the frame to the real
   url. PDFs, images and plain text pass through unchanged; any other type is
   redirected to the real url. Only documents ever go through the Worker.

Hosts with an underscore in a label (`wauth_subspace.arweave.net`) are a special
case: the Workers runtime, like every OpenSSL-family TLS stack, does not match
such a name against a wildcard certificate, while browsers do. When fetching an
allowed host of that kind fails, the Worker answers `302` to the real url and
lets the browser try, instead of calling the site dead.

Stripped from proxied responses: `X-Frame-Options`, `Content-Security-Policy`
(and `-Report-Only`), `Cross-Origin-Opener/Embedder/Resource-Policy`,
`Set-Cookie`, `Report-To`, `NEL`, `Clear-Site-Data`, `Strict-Transport-Security`,
`Refresh`, `Service-Worker-Allowed`, `Alt-Svc`, CORS headers. Added:
`X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: strict-origin`,
`Cache-Control: private, no-store`, and `X-Link-Proxy` (`proxied`, `redirect`,
`dead`, `blocked`, `interstitial` or `refused`) for debugging.

### `GET /check?url=<url>`

```json
{ "ok": true, "status": 200, "finalUrl": "https://…", "frameable": false,
  "dead": false, "wayback": null, "reason": null }
```

`reason` is `null`, `"dead"`, `"blocked"`, `"unverified"` (an underscore host
the Worker could not fetch, see above) or `"not-allowed"` (redirected off the
allowlist; `status` is `0` and `finalUrl` is `null`, since that hop is neither
requested nor disclosed). `wayback` is a snapshot url when `dead` is true and
one exists.
Errors: `400 {"ok":false,"error":"bad-url"}`, `403 {"ok":false,"error":"forbidden"}`
(caller is not the site), `403 {"ok":false,"error":"not-allowed"}` (host not on
the allowlist).

### `GET /gif/search?q=<text>&limit=<1-50>` and `GET /gif/trending?limit=<1-50>`

Forward to Klipy's `v2/search` and `v2/featured` and return Klipy's JSON
unchanged: `{ "results": [{ "id", "title", "content_description", "url",
"media_formats": { "tinygif": { "url", "dims", "size" }, "nanogif", "gif",
"mediumgif", … } }], "next": "…" }`. `limit` defaults to 20; `pos=<next>` pages.
Errors are JSON: `400 missing-q`, `403 forbidden`, `503 gif-not-configured`,
`429 rate-limited` (with `Retry-After: 60`), `502 upstream-error` /
`upstream-unreachable`.

### `GET /health`

Plain `ok`. Everything else is `404`.

### `POST /mcp` — MCP server

A stateless [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)
MCP server. Every request is one POST and gets one `application/json`
response; there are no sessions, no SSE streams and no server-to-client
requests. It is public (no sign-in) because everything it returns is already
published on the site.

| Tool | Arguments | Returns |
| --- | --- | --- |
| `search_site` | `query` (≤ 200 chars), `section` (`any`, `blog`, `project`, `timeline`, `page`), `limit` (1–20, default 8) | Best matches with url, markdown url, date, tags, description and an excerpt |
| `list_posts` | `tag`, `limit` (1–50, default 20) | Blog posts, newest first, plus every tag in use |
| `list_projects` | `tag`, `include_archived` (default `true`), `limit` (1–60, default 40) | Projects, newest first, with an `archived` flag, plus tag counts |
| `get_page` | `page`: a site url, a path (`/blogs/pokemon-scanner/`) or a bare slug (`pokemon-scanner`) | The page's markdown twin (`<page>index.md`); `/` returns `/llms.txt`; old addresses follow Hugo's alias pages |
| `get_about` | none | `/about/index.md` |
| `get_resume` | none | `/resume/index.md` and the PDF link |
| `get_contact` | none | The "Elsewhere" list of `/about/index.md` (socials, email, booking link) |

All tools carry `readOnlyHint: true`; the search and list tools also declare an
`outputSchema` and return `structuredContent` next to a readable text block.
Bad arguments come back as a tool result with `isError: true` and a message the
model can act on; an unknown tool is a JSON-RPC `-32602`.

**Where the data comes from.** Only from files the Hugo build publishes:
`/index.json` (the Spotlight index: titles, descriptions, dates, tags and the
first 600 characters of each page), `/projects/index.md` (archived flags) and
the per-page `index.md` twins. Fetches go to `SITE_URL` only, with a 6 second
timeout and a 2 MB cap, and are cached for 5 minutes (Cloudflare cache, plus
the parsed index in the isolate; a stale index is served if a refresh fails).
Nothing is written anywhere and no secret is read.

**Protocol versions.** Dual-era, on the same endpoint:

- *Modern* (`2026-07-28`): no handshake; every request carries
  `_meta["io.modelcontextprotocol/protocolVersion"]` and
  `clientCapabilities`. The `MCP-Protocol-Version`, `Mcp-Method` and (for
  `tools/call`) `Mcp-Name` headers must match the body, else `400` with
  `-32020 HeaderMismatch`. `server/discover` is implemented; results carry
  `resultType: "complete"`, `serverInfo` in `_meta`, and `ttlMs`/`cacheScope`
  on `server/discover` and `tools/list`. Unknown methods are `404` + `-32601`.
- *Legacy* (`2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`):
  `initialize` echoes a version it speaks (or offers `2025-11-25`) and mints
  no `Mcp-Session-Id`; `notifications/initialized` gets `202`; requests without
  an `MCP-Protocol-Version` header are taken as `2025-03-26`.
- Any other version: `400` with `-32022 UnsupportedProtocolVersion` listing
  the supported ones.

`GET` and `DELETE` on `/mcp` are `405` (no standalone stream, no sessions).
JSON-RPC batches are refused (`-32600`).

### `GET /.well-known/mcp.json`

The server card (also at `/.well-known/mcp/server-card.json`): name, title,
description, version, website, supported protocol versions and
`remotes: [{ "type": "streamable-http", "url": "<worker>/mcp" }]`. Tools are
deliberately not listed; clients get them from `tools/list`. The site publishes
the same card at `https://ankush.one/.well-known/mcp.json` when `linkProxy` is
set; if you change `SERVER_VERSION` or the description in `src/mcp.js`, change
`layouts/partials/agents/endpoints.md` too. Server cards are still a draft
proposal (SEP-1649 and successors), so the file name may move.

Connect a client to `<worker>/mcp`, e.g. in Claude Code:
`claude mcp add --transport http ankush https://ankush-site-worker.<account>.workers.dev/mcp`.

### `GET /search?q=<terms>&section=&limit=&format=`

The `search_site` ranking for agents that only have a web-fetch tool, and the
answer-friendly side of the desktop's `?q=` search (which is Spotlight, a
JavaScript UI that a fetcher cannot read).

- `q` is required (at most 200 characters). Optional `section`
  (`any|blog|project|timeline|page`), `limit` (1 to 20, default 8) and
  `format` (`md` or `json`). Bad input is a `400` with a usage line.
- Default answer is `text/markdown`: a heading, each hit as a link with its
  section, date, tags, description, the matching excerpt and the address of
  its markdown twin, then pointers to llms.txt and `/mcp`. `format=json` (or
  `Accept: application/json`) returns
  `{query, section, total, results: [...]}` with the same item fields as the
  MCP tool's `structuredContent`.
- When the best hit is a short standalone page (section `page`: about,
  resume, privacy and the like, up to 6,000 characters), its markdown is
  included in full under the list (`top_result_markdown` in JSON), so
  "how do I contact him" is answered in one fetch. Posts and projects stay
  links. App entries in `index.json` have no body text, so About also
  matches a fixed set of contact words (`APP_KEYWORDS` in `src/mcp.js`:
  contact, email, socials, book a call and the like); keep that list in step
  if the contact list moves to another page.
- A browser navigation (`Accept: text/html` and no `format`) gets a `302` to
  `<SITE_URL>/?q=<terms>`, which opens the desktop with Spotlight filled in,
  so the address is safe to hand to people as well.
- No results is still a `200` with a short note. Responses carry
  `Cache-Control: public, max-age=300`, `Vary: Accept` and CORS `*`.

```sh
curl -s 'https://ankush-site-worker.<account>.workers.dev/search?q=solana&limit=3'
```

## Abuse protections

This must not become an open proxy. Every proxy request has to pass all of:

- **Method**: `GET`/`HEAD` only.
- **Target**: absolute `http(s)` url on the default port, no credentials, at
  most 2048 characters; IP literals (including hex/decimal forms), `localhost`,
  bare names and `.internal`/`.local`/`.lan`/`.test`-style hosts are refused, as
  is the Worker's own host.
- **Frame only**: when the browser sends `Sec-Fetch-Dest` it must be `iframe` or
  `frame`. `fetch()`/XHR, `<script>`, `<img>` and service-worker requests are
  refused, so scripts on other sites cannot use the Worker to read pages. A
  top-level visit gets a small page pointing at the real url instead of proxied
  content.
- **Referer**: its origin must be one of `SITE_ORIGINS`, or the Worker itself
  (navigation inside the frame). Requests with no Referer are refused with a
  small page that links to the real url; nothing is fetched.
- **Allowlist**: the target host, and every host a redirect chain passes
  through, must be linked from the site (`ALLOWLIST_URL`), in `EXTRA_HOSTS`, or
  be `web.archive.org`. Each hop is also re-checked against the **Target**
  rules, so a redirect cannot point the Worker at an IP literal, a port or an
  internal name. The list is cached for an hour (in the isolate, and through
  the Cache API where it is available). If it cannot be loaded and the isolate
  has no earlier copy the Worker **fails closed**: only `EXTRA_HOSTS` and
  `web.archive.org` are allowed, and it retries after a minute.
- **Upstream request**: only `User-Agent`, `Accept` and `Accept-Language` are
  forwarded. No cookies or `Authorization`, so the Worker never acts with a
  visitor's identity. 10 second timeout.
- `/check` and `/gif` need an `Origin` (or Referer) in `SITE_ORIGINS`, and CORS
  only ever echoes those origins. Klipy error bodies are not relayed.

`Referer` and `Sec-Fetch-Dest` are trivially forged by non-browser clients, so
they stop other *websites* from using the Worker, not `curl`. What bounds a
determined script on the proxy is the allowlist: the most it can fetch is a
public page on a host the site already links to, without credentials.

`/gif` has no allowlist to fall back on, so against non-browser clients the
Klipy key is only rate-limited, not origin-protected: a script that forges the
Origin can still search Klipy through the Worker, at most 60 requests a minute
per IP and Cloudflare location (`MCP_RATE_LIMITER`, key `gif:<ip>`, answered
`429` beyond that). The key itself never leaves the Worker.

The same bound applies to scripts on a proxied page. Every proxied document
shares the Worker's origin, so such a script can load another allowlisted page
through the Worker in a nested iframe and read it. What it gets is what anyone
can fetch anonymously from those hosts, and nothing of ankush.one's.

On the site side the proxied iframe is sandboxed without `allow-top-navigation`
(a proxied page cannot navigate the desktop away) and uses
`referrerpolicy="strict-origin-when-cross-origin"`, which the Referer gate needs.

### `/mcp`

The MCP server is open to anyone by design, so its protections are about cost,
not access:

- It can only ever fetch from `SITE_URL`. `get_page` accepts a url only when its
  host is the site's, and a path only from `[A-Za-z0-9._~/-]` with no `..`
  segment; it reads `<path>index.md` and nothing else. There is no way to make
  it request another host.
- Request body at most 16 KB (`413`), `Content-Type: application/json` only
  (`415`), one message per POST, string arguments capped (query 200, tag 40,
  page 300 characters), result counts capped, page text cut at 50,000
  characters with a pointer to the rest.
- 60 requests per minute per IP (`MCP_RATE_LIMITER`), answered with `429`,
  `Retry-After: 60` and a JSON-RPC error.
- `Origin` is checked as the transport spec requires: absent (non-browser
  clients), any `https:` origin, or `http://localhost` / `127.0.0.1` pass;
  anything else, including `null`, is `403`. CORS is `*` because the data is
  public and no credentials are involved.
- Peer-supplied strings are never reflected into HTML; responses are JSON with
  `X-Content-Type-Options: nosniff` and `X-Robots-Tag: noindex`.

### `/search`

Same rules as `/mcp`: it only reads `SITE_URL` (the index, the projects list,
plus at most one markdown twin of a page from that index), `q` is capped at 200 characters, and
it has its own 60 per minute per IP budget in `MCP_RATE_LIMITER` (`429` with
`Retry-After: 60`). The echoed query only ever appears in `text/markdown` or
JSON with `nosniff`, never in HTML.

## Known limits

- **All proxied sites share the Worker's origin**, so they share its
  `localStorage`/IndexedDB with each other. Nothing of ankush.one's lives there,
  and no cookies are set, but do not add hosts you would not want next to each
  other.
- Pages are fetched anonymously from Cloudflare's network: visitors are never
  logged in, and some sites answer datacenter addresses with a bot wall (shown
  as "cannot be shown in a window").
- Single-page apps that route on `location.pathname` see `/` instead of their
  own path and may render their home or not-found view. `history.pushState` is
  shimmed so they do not crash, but there is no fix short of a full rewriting
  proxy.
- Requests made by a proxied page's own scripts go to its real origin with the
  Worker as `Origin`; APIs that are same-origin only will fail.
- A frameable site is handed off with a `302`; from then on its links are its
  own business and never touch the Worker.

## Free plan budget

Workers Free allows 100,000 requests per day and 10 ms of CPU per request.

- One window opening costs one request (two when a dead page leads to a
  snapshot). Subresources never touch the Worker. `/check` and `/gif` are one
  request each.
- CPU time excludes waiting on the network. Gates and redirects use well under
  1 ms. `HTMLRewriter` parses in native code, but every element handler is a
  call into JavaScript, so handlers are only registered for elements that
  occur a handful of times per page (`head`, `body`, `base`, `title`, `link`,
  `style`, `script`, `meta`, `form`). Links are deliberately left to the
  injected script: rewriting each `a[href]` cost roughly 12 microseconds, which
  put pages with around a thousand links over the limit. A 20,000-link test
  page now takes about the same time as one without links.
- If a page does exceed the limit while it is streaming, the document is cut
  off part-way rather than replaced by an error page; the window's "Open in new
  tab" control still works.
- Each request makes at most 11 subrequests (allowlist, up to 9 for the target
  and its redirects, Wayback); the limit is 50.
- When the daily quota is spent Cloudflare answers `429`/error 1027 until
  00:00 UTC. The site keeps working; proxied windows show Cloudflare's error.
- `/mcp` costs one request per tool call and at most three subrequests (index,
  projects list, page). Measured locally: parsing the index about 0.6 ms (once
  per isolate per 5 minutes), a six-word search over every page about 0.4 ms,
  list and page tools about 0.1 ms.
- `/search` costs one request and at most three subrequests (index, projects
  list, and the top page's markdown when it is inlined).

## Local development

```sh
npx wrangler dev --local --port 8787 \
  --var SITE_ORIGINS:https://ankush.one,http://localhost:1313 \
  --var ALLOWLIST_URL:http://127.0.0.1:1313/external-hosts.json \
  --var EXTRA_HOSTS:github.com,example.com

# a frame-blocking site is proxied (X-Link-Proxy: proxied, <base> injected)
curl -si 'http://127.0.0.1:8787/?url=https%3A%2F%2Fgithub.com%2FankushKun' \
  -H 'Referer: http://localhost:1313/' -H 'Sec-Fetch-Dest: iframe' | head -20
```

`--var KLIPY_API_KEY:<key>` (or a `.dev.vars` file, which is git-ignored)
enables `/gif` locally.

To try the MCP server, build the site with a local base URL, serve it, and
point `SITE_URL` at it:

```sh
hugo --baseURL http://localhost:8793/ --destination /tmp/site-build
python3 -m http.server 8793 --bind 127.0.0.1 --directory /tmp/site-build &
npx wrangler dev --local --port 8787 --var SITE_URL:http://localhost:8793

# modern (2026-07-28) request: no handshake, headers mirror the body
curl -s http://127.0.0.1:8787/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2026-07-28' -H 'Mcp-Method: tools/call' -H 'Mcp-Name: search_site' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"search_site","arguments":{"query":"solana"},
       "_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}'

# legacy clients start with initialize
curl -s http://127.0.0.1:8787/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

`npx @modelcontextprotocol/inspector` gives a UI for the same endpoint.
The plain search runs on the same dev server:
`curl -s 'http://127.0.0.1:8787/search?q=contact'` (add `&format=json` for JSON).
