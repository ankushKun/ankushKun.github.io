# ankush.one

Personal site built with Astro and Tailwind. Static output. Client JavaScript is the page router (Astro's `ClientRouter`), the 3D plaza (the home page only), the music radio, your Mii on the About page, the Mii viewer at `/mii/`, the apps, the UI sounds and analytics. Every page works without it.

```sh
pnpm dev      # http://localhost:4321
pnpm check    # type check content and templates
pnpm build    # static site in dist/
pnpm favicons # save the icons of linked sites (after adding links)
```

## Deploying

Pushing to `main` deploys the site to GitHub Pages from `ankushKun/ankushKun.github.io` (`.github/workflows/deploy.yml`): it installs with pnpm, runs `pnpm check` and `pnpm build`, and publishes `dist/`. Pull requests run the same check and build without deploying, and the workflow can be run by hand from the Actions tab. The custom domain is set in the repo's Pages settings rather than by a `CNAME` file, since the site deploys from a workflow. `ankush.one` is proxied through Cloudflare, which serves HTTPS and redirects plain HTTP, so GitHub can't issue its own certificate and Enforce HTTPS stays off there. The repo has to be named `ankushKun.github.io`: only the user site's domain carries the other repos' Pages, so `ankush.one/3dsDL/` and the rest keep working. GitHub Pages matches addresses exactly, so the 404 page sends one in the wrong case on to the right spelling before anything is drawn: lowercase, or the repo's own name for those with capitals (`CASED_SITES` in `src/site.ts`, where a new one goes).

## Link previews

Every page has its picture's alt text (`og:image:alt`, `twitter:image:alt`), and entries give Slack two short facts under the link (`facts` on `Base.astro`: when and how long for a post, year and stack for a project; on the home page, what I'm building and how many projects I've shipped). The home page also has:

- **A clip** (`og:video`, `public/media/plaza-preview.mp4`): eight seconds of the live plaza that loop without a cut, which iMessage plays in the bubble, Discord over the picture and Telegram large.
- **A player on X**: share `ankush.one/x/` on X and the post plays the live plaza (`/player/`, the plaza alone, Base.astro `embed`: settled from the start, links open the site in a new tab), with the home page's card as the still. `/x/` (`pages/x.astro`, Base.astro `player` and `redirect`) carries the player card and sends anyone who opens it on to the home page. It's a link of its own rather than tags on the home page because iMessage and Telegram read the same tags and would draw a player card as a small picture; links to `ankush.one/` keep the large card and the clip.

The cards' backdrop (`src/assets/og/plaza.jpg` with `plaza.json`) and the clip are recorded from the real plaza by `pnpm og:capture` while `pnpm dev` runs: headless Chrome on virtual time, with the chat and the radio blocked so nobody's messages end up in them. Run it again after the plaza changes look.

## AI agents (AEO)

The site follows the AEO Spec v1.0 ([dualmark.dev](https://dualmark.dev/docs/spec/overview)), so answer engines can read and cite it:

- **Markdown twins** (`src/lib/twins.ts`, built by `pages/[...twin].md.ts`): every page that is something to read has a Markdown copy at its path with `.md` for the trailing slash: `/index.md` for the home page, `/blogs/<slug>.md` for a post, `/about.md`, `/blogs.md` for the list, and so on. Each is made from the same content as its page: the title and description, the facts (dates, tags, stack), the page's own Markdown with site links made absolute and pictures pointed at their built files, its links and FAQ. Home, About, Contact, Resume, Apps and Games add what their pages show from `src/data/` and `src/site.ts`. `/sitemap.md` lists every twin. Each page names its twin in a `<link rel="alternate" type="text/markdown">`. Interactive pages (the apps themselves, the Mii viewer) have none.
- **GitHub Pages only.** The site, and the other repos served under `ankush.one/*`, are GitHub Pages, so nothing sits in front of them: the twins are served as GitHub serves `.md` files, and the spec's checks for response headers (`X-Markdown-Tokens`, `X-Robots-Tag`, `Vary`, a `Link` header) and for answering by `Accept` or user agent are left unmet on purpose.
- `robots.txt` lets every crawler in, and `/llms.txt` lists the site for language models.

## Analytics

PostHog on EU Cloud, reached through the first-party proxy at `p1.ankush.one` (`POSTHOG` in `src/site.ts`, where an empty key turns it off). It's the same project the standalone sites under ankush.one (3dsDL, sh23ds, mixtunes) send to, and each event says which site it came from in `site` (`ankush.one` here). `src/scripts/analytics.ts` is the only file that imports `posthog-js`. It runs only on `ankush.one` and loads once the browser is idle. The router keeps one document for the whole visit, so PostHog's own pageviews are off and the module sends a `$pageview` (with `section` and `not_found`) on every `astro:page-load`, and a `$pageleave` before each move. Autocapture, heatmaps, dead clicks, exceptions, web vitals and session replay are on, with typing masked and canvases (the plaza, Paint) recorded at 2 fps. Joining a live app identifies the browser by its live-app id, with the nickname as `name`. The PostHog project needs session replay switched on, and `https://ankush.one` in its authorized URLs for the toolbar.

- **Adding an event:** add it to `Events` in `analytics.ts` with its properties, then call `track('name', { ... })` where it happens. Names are `object_verb`, past tense.
- **Keeping something out:** the `ph-no-capture` class drops an element from replays and autocapture, as on the Guestbook's email badges.
- **Trying it locally:** `PUBLIC_POSTHOG_DEV=1 pnpm dev`. PostHog marks events from `localhost` as a test user's.
- **Not seen:** the Markdown twins, `llms.txt` and the feeds are plain files, so agents and feed readers only show up in Cloudflare's logs. Visitors can turn analytics off on `/privacy/`.

## Adding content

Every entry is a folder with an `index.md` and its images. The folder name is the URL.

| Section | Folder | URL |
| --- | --- | --- |
| Blog | `src/content/blog/<slug>/` | `/blogs/<slug>/` |
| Projects | `src/content/projects/<slug>/` | `/projects/<slug>/` |
| Timeline | `src/content/timeline/<slug>/` | `/timeline/<slug>/` |

Copy an existing entry to start a new one. All entries share `title`, `description`, `date`, `updated`, `tags`, `cover`, `coverAlt`, `canonical`, `links`, `faq`, `related` and `draft`; each section adds a few fields of its own, defined in `src/content.config.ts`. The build fails if a required field is missing.

`cover` is optional: when set, it is used for the list thumbnail, detail hero image, and social preview. When omitted, a 1200x630 card is generated at build time by `src/lib/og.ts` (`/og/<section>/<slug>.jpg`) for list thumbnails and social previews: your Mii up close in the plaza, with its pixel name tag, beside a Miiverse style post holding the section's block art, a name pill, the title, the description and a date or year. `description` is the meta description, social card text, RSS summary and `llms.txt` line, so keep it to one clear sentence. `draft: true` shows the entry in dev only.

Standalone pages (About, Privacy, Credits...) and the intro of every section index are Markdown files in `src/content/pages/`, named after the page. Resume data lives in `src/data/resume.ts` and also feeds the About page. Name, socials, nav, booking link and newsletter form target live in `src/site.ts`.

## Every other page

Every page but the plaza is shown on a TV (`src/components/ui/Frame.astro`): a white casing round a pale screen with a CRT's rounded corners, and one white column down the middle of the screen, as wide as two thirds of it, to read. The page scrolls under the casing's edge as under glass. Nothing else is on the screen:

- **Top left**, a round button back to the plaza. **Top right**, a round button that opens the menu of sections (`NAV` in `src/site.ts`): their glass tiles drop out of it one under another (`src/scripts/menu.ts`), each with its name on a dark tag to its left (the section you are in has a blue one), and fold back up into it when it closes. It stays open, without dimming the page, until the button or Escape closes it, and on a big screen it stays open as you go from page to page. Icons are frosted glass like the Wii U home menu's (`--aero-*` in `global.css`).
- **The footer** at the end of every page links the rest of the site (`FOOTER_NAV`): home, the sections, privacy, credits and the RSS feed.
- **On a phone** the casing is thinner, the column fills the screen under the two buttons, the buttons step aside while you read down a page and come back when you scroll up.
- **Lists**: the blog is rows of posts under their year (`Feed.astro`); projects are glossy channel tiles, more across as the column widens (`ChannelMenu.astro`); the timeline is memos dated by little calendar pages colored by kind (`Timeline.astro`); apps are the Wii's channel menu (`apps.astro` on `ChannelGrid.astro`): wide channels in glossy frames, art edge to edge with the name across the top (the app's own banner from `src/assets/channels/<slug>.webp`, painted 16:9 on white in the style of the block art with its scene kept below the name, which is then grey; else a wide crop of its block art; else a drawn banner, `/art/channel/<slug>.svg`), always whole pages of twelve with grey empty channels in the free slots, two, three or four across by the room the menu has; games (`games.astro`) are the same menu, every game in `src/data/games.ts`, each opening its own page (see Games).
- **Entries** (`layouts/Entry.astro`) read top to bottom: the B button back to the section, the title, a byline signed by your Mii, the picture, then the text. Standalone pages (`layouts/Page.astro`) are a title and their text; sections of a longer page are `Panel.astro`, a heading with what is under it.
- **Light** is the default, whatever the device prefers; pick dark with the icon out in the casing's top right corner, or at the top beside the plaza button on a phone (`ThemeToggle.astro`, `src/scripts/theme.ts`); picking light again forgets the choice. The dark TV has a black casing and a charcoal column. Colors that change are `light-dark()` pairs on the tokens in `global.css`. On the TV the new lights spread in a circle from the icon; on the plaza it turns to night, the floor, haze and fog dimming over about half a second (`setNight` in `plaza/floor.ts`). The theme is set before the page draws, so it never flashes.
- **Icons** on the TV's buttons and the light switch are [Hugeicons](https://hugeicons.com) (`@hugeicons/core-free-icons`), drawn at build time as inline SVG by `HugeIcon.astro`.
- **Link buttons** (`MenuButton.astro`) are one design everywhere: the console's plain glossy surface, a badge, the label, and an end mark for what pressing it does (an arrow opens a new tab, a chevron stays on the site, a down arrow downloads). Color only lives in the badge, which `src/lib/links.ts` picks from the href: a platform's real mark from [Simple Icons](https://simpleicons.org) (`src/lib/platforms.ts`, one row per platform), else the site's own icon, else a section's tile for pages here, else a glyph. The label is always the one written, so give every `links:` entry a label that says what it opens ("3dsDL", not "Website"). Entries and the 404 go back with `BackButton.astro`, made the same way.
- **Site icons** for links to sites without a platform mark are saved by `pnpm favicons` (`scripts/favicons.mjs`) into `public/favicons/`, with `src/data/favicons.json` saying whether each fills its badge or sits on a white tile. Both are committed, so the build never goes online. Run it after adding links; a site with no usable icon gets a globe.
- **Links out of the site** open in a new tab with a small arrow after them: Markdown through a Sätteri plugin (`src/lib/external-links.ts`), short data strings through `inline()`, templates through `extAttrs()` (`src/lib/external.ts`). Astro caches rendered Markdown, so after changing the plugin delete `node_modules/.astro/data-store.json` before building.
- **Sounds** are made on the spot (`src/scripts/sfx.ts`): a tick when you point at something, a chime when you press it. `M` mutes them and the music. `B` goes back.
- **Music** plays across the whole site (see Music below). Its widget (`src/components/music/Widget.astro`) sits in the casing's top left corner, mirroring the light switch (beside it on a phone, left of it on the plaza, in the bar on an app's screen): a note that turns into dancing bars while music is heard, the track's name on a dark tag for a moment when it changes, and a small player (art, seek, previous, play, next, volume, Open Music) that drops out of it, as far from the side of the screen as from the top (centred on a phone).
- **Mii portraits** (`public/mii/`) are rendered from `ME`: neutral, happy, surprised, and a full-body one for the 404. Re-render them if `ME` changes.
- Entries without a `cover` get drawn art from `/art/<section>/<slug>.svg`, picked from their tags (`src/lib/tiles.ts`). Sections without a plaza block take their tile's glyph and colors from `TILES` in `src/data/sections.ts`.

Moving between pages follows one model (`src/scripts/motion.ts`, the end of `global.css`, `plaza/main.ts`):

- **Plaza and pages.** The plaza is the room and the TV the screen in it. Press a block and the camera zooms into it until it fills the screen, the plaza fading away into its haze on the way, and then the page fades in. Come back (the plaza button, the footer's Home, or Back) and the page fades out as the plaza fades in close on the block of the section you were in and pulls back from it. These go through the router like every other move (`html[data-plaza-move]`), so the site is one document for the whole visit and the music never stops. Once the plaza has run it is kept: on other pages it sleeps out of sight (no frames, its clock stopped; every page holds a place for it with `transition:persist`, and `motion.ts` drops a place the plaza never filled), and coming back wakes the same plaza.
- **On the TV** every page change is a plain fade: the casing, buttons and menu are one element throughout and stay in front, and only the column fades out and the next one in.
- **Apps** are the screen going full size: the casing slides off past the edges as the app grows in, and back as you leave. Opened from its channel on `/apps/`, the channel itself grows into the app and the app shrinks back into it (`data-grow`).
- A page opened directly (its address, a refresh, another site) fades in on its own.
- Every move takes one of three lengths, `--vt-out`, `--vt-in` and `--vt-big` in `global.css`. The app moves animate transforms only (`boxMove` in `motion.ts`), so they stay smooth while the app starts up underneath. Reduced motion turns them into short fades. Without JavaScript every link is a normal page load.
- `pnpm transitions` films every move on desktop and phone against `pnpm preview` and writes a sheet of frames for each into `.transitions/` (`scripts/transitions.mjs`; it needs `pnpm add -D playwright-core`, and ffmpeg for the sheets).

## Apps

Apps live at `/apps/<name>/` and take the whole screen instead of the reading column (`app` on `Base.astro`, `.col-app` in `global.css`): the TV's casing slides off past the edges as you go in and back as you leave (a channel grows into its app, see Moving between pages), and the plaza button stays in the top left. An app with a rail of its own (the chat) lists the sections there instead of the TV's menu: Menu in the rail unfolds them under it and folds them away, the rail scrolls when the screen is short, the TV's menu button stays hidden (`data-app-nav`), the menu folds away if it was open as you came in, and the light switch moves into the app's bar. On a phone the rail goes and both buttons stay in the bar. The list on `/apps/` is `src/data/apps.ts`; an app with an `href` opens, one without shakes its head. An app's plaza block, tile and art are keyed by its `href` once it has one (`appPath`), so a live app's block opens the app itself (`/apps/chat/`, `/games/`) and one marked `soon` opens a placeholder at its href (`pages/apps/[app].astro`, `AppSoon.astro`): its art, what it will be, and the way back. Every game on `/games/` has a page of its own the same way (`pages/games/[game].astro`) with its play links, where it will run once it is embedded.

### Music (`/apps/music/`)

The site's radio, and an iTunes 11 style player for it (`src/components/music/`): a toolbar with previous, play, next and volume on the left, the LCD in the middle (art, title, artist, seek, shuffle and repeat), search on the right, Cover Flow under it, on a pale stage by day and a black one by night, each cover mirrored on the floor (arrows, the wheel or a swipe move along; pressing the middle cover plays it), the songs (press one to play it, the headers sort) and a status line. On a phone Cover Flow and search make way.

- **Playback** is YouTube's IFrame player, hidden (`src/scripts/music/youtube.ts`), as on the old site: no audio is stored here. It is mounted on `<html>` itself, outside the `<body>` the router swaps, so it is never moved or reloaded. `engine.ts` is the one radio the widget, the app and the plaza all show: queue, shuffle (on by default, never one of the last few heard), repeat, fades, Media Session (lock screen and media keys), and one tab playing at a time (`BroadcastChannel`).
- **The plaza starts it.** The opening plays the plaza's own theme; once the crowd is in (or as soon as the opening is skipped, or you leave the plaza) the theme fades out as a random track fades in (`takeOver` in `engine.ts`, `release` in `plaza/audio.ts`). The two never play together. If YouTube can't be reached, or you stopped the music earlier in the session, the theme plays on. Each new track, the DJ says what it is in a bubble that opens the music player over them, and while it plays the Music block shows its cover with bars dancing over it (`plaza/nowplaying.ts`; they keep time on their own, since YouTube's sound can't be read from the page).
- **The DJ** stands under the Music block with a boombox on their shoulder, in a clear space of their own, facing out. Nobody else stands on the stage, and anyone walking by goes round it (`STAGE` in `plaza/crowd.ts`), so no one is left hidden behind the dancers. The three are a wall (`WALL`): nobody walks through them, and a Mii thrown at them bounces off while they stand firm. While music is heard, now and then someone from the crowd near the stage runs over to dance along, in one of four places carrying the dancers' row on either side, for 15 to 30 seconds or until the music stops, then walks back (`FANS`, `recruit`). While music is heard they set the boombox down on the floor in front of them (it hops down, and back up to the shoulder when the music stops), dance with both hands free, and it thumps on the beat while notes float up out of it (`plaza/boombox.ts`). Pressing them, or their button with the keyboard, opens the music player over their head, the same player the widget opens, and it follows them while it is open (`openOver` in `src/scripts/music/widget.ts`). They can't be picked up. Either side of them dance Akita Neru and Kasane Teto (`BACKUP` in `src/data/plaza.ts`, made there from Miku's face with their own hair, eyes and shirts): while music is heard all three dance the same routine as one, square on to you (`idol` in `plaza/motion.ts`). It is matched frame by frame to a recording of a chibi Miku dance that loops every 1.775 s: poses keyed in `ROUTINE`, their arms measured as where the upper arm and forearm point and solved for a Mii's joints, eased between with curves that never overshoot. Every other loop is danced mirrored, so the pivot goes right, then left, swapping sides at the hands on hips. On stage they wear short sleeves (`sleeves` in `MiiSet`), bare forearms in their own skin color, so arms crossing the body show. They dance to the beat of whatever the radio plays (`BeatClock` in `plaza/beat.ts`): each track's beat is measured once by `pnpm bpm`, and the routine is fitted to it 2, 4 or 8 beats at a time, whichever is nearest its own pace (`LOOP`, the recording at 72% speed), each time round starting on a bar, following the player's position in the track every frame. A new track or a change of tempo eases them onto the new beat rather than jumping, and with no beat to follow they keep their own pace. Each dancer is a touch ahead of or behind the beat (`LAG`, picked afresh each visit), so the three never move as one machine. Tap one and they react as anyone would, then dance on. Who the DJ is (`DJ`, Hatsune Miku) and which boombox (`BOOMBOX`) live in `src/data/plaza.ts`: `model` is Supersiv11's low poly boom box (`public/plaza/boombox.glb`, CC BY, 596 triangles, 11 KB after `gltf-transform optimize --compress meshopt`), `drawn` is built in code in the plaza's own style. In `pnpm dev`, `__plaza.boombox('drawn')` swaps them on the spot, and `__plaza.groove()` sets the stage dancing without the radio.
- Every load starts quiet, at 33%. Nothing else about playback is kept across loads, except that you stopped it, which holds for the session.
- A game (`play.ts`) or a video on a page holds the music: it fades out and comes back when they end. If the browser blocks a start, the next press anywhere starts it; on iOS the press that starts the plaza also unlocks the player silently, so the handover can play later.
- The mix is `src/data/music.json` with square covers in `public/music/covers/`, synced from the YouTube playlist by `pnpm music` (`scripts/music.mjs`, needs `yt-dlp`): metadata and thumbnail stills only. Titles and artists already in the file win over YouTube's, so fix a name there by hand and it stays fixed. Songs that aren't on the playlist go in `src/data/music-extra.json` (`videoId`, `title`, `artist`) and follow the playlist's, marked `byHand`; `pnpm music --extra` adds them without reading the playlist again. The Vocaloid songs for the DJ and their dancers are there. A song on the playlist that shouldn't play goes in `src/data/music-skip.json`, and the next sync leaves it out too.
- Each track's beat is measured by `pnpm bpm` (`scripts/bpm.mjs` with `scripts/tempo.mjs`, needs `yt-dlp` and `ffmpeg`) for the stage to dance to: its tempo (`bpm`) and a short map of its steady stretches (`beats`, each a bar's start in seconds and the tempo from there, so tempo changes are followed). The audio streams through ffmpeg into memory and is dropped once measured; nothing is saved but the numbers. Only tracks without a `bpm` are measured, so run it after `pnpm music` adds some (it says so); name video ids, or pass `--all`, to measure again. A track with no steady beat gets `bpm: null`.
- In `pnpm dev`, `__music.state` in the console shows the radio and `__music.log` every player state change and page swap: a page change should never log a pause or buffering.

### Chat (`/apps/chat/`)

A live chat room drawn as Miiverse was on the Wii U (`src/components/chat/`): a white rail down the left with your Mii, the people here, Menu (the site's sections, folding out under it) and Back (B), a green title bar with the faces of who is here, posts with each person's Mii beside a white card, and the Post button in the screen's bottom right corner. On a phone the rail goes and the bar holds the plaza and menu buttons.

- **No server of our own.** It talks to the GUN relay at `gun.ankush.one` (one connection for every live app, `live/relay.ts`), on the same nodes the old site's IRC chat used, so the room and its history carried over and old clients still interoperate. `net.ts` lists the chat's nodes and checks everything read from them before the page sees it; text is only ever drawn as DOM text (`format.ts`).
- **Everyone is their Mii.** Joining gives you a random Mii from the Mii Maker's own generator; the Me sheet rolls another or loads one from a Mii QR code. Your Mii is stored once per person (`apps/irc/profiles/<uuid>`), so changing it updates everything you have said. Anyone without one (everyone from the old site) gets a stand-in made from their id or name (`seededMii` in `mii/rig.ts`), the same on every screen. A Mii code is either the 96 bytes of a QR code Mii or, for Miis made on the spot, an FFL CharInfo (`miiBytes` in `mii/data.ts`). `portraits.ts` photographs a Mii once in Miiverse's six feelings on one small offscreen canvas, newest asked for first so the posts on screen get theirs first, and caches the pictures; without WebGL a silhouette stands in.
- **Posts**: pick a feeling for your next post from the Me sheet (your Mii's face changes with it), write with a little Markdown, links and @mentions (an @ lists people to pick from, those here first, and a name that belongs to someone shows in their colour as you type: `mentions.ts`, a coloured mirror behind the text box), or draw: the pen button opens a sheet over the input bar with Miiverse's 320 by 120 black and white paper, a pen, a marker, an eraser, undo (also Cmd or Ctrl + Z) and clear, and its own Post. A drawing stays on the paper if you close the sheet, until you post or clear it. The GIF and drawing sheets open in the same place (`sheets.ts`). Everyone's name shows in a colour of their own, a hue hashed from their id rather than their name, so it stays when they rename (`hueOf` in `main.ts`). Cards are as wide as what they say, the time sits by the name, and each day starts under a divider. Yeah! and Delete sit in a slot beside each card, so pointing at a post never moves the feed. Delete is yours to use on your own posts; names in `CHAT_MODS` (`src/site.ts`) can delete anyone's. The relay has no accounts, so that is moderation by courtesy: anyone could take a mod's name or write to the relay directly. Slash commands (`commands.ts`, one list behind parsing, `/help` and the picker) cover the old chat's and more: faces, ASCII art (posted as a ``` block, so it stays plain text every client reads), `/cowsay`, `/sign` and `/box` around your words, text effects, dice and coins, and things to do to someone. Typing a / alone in the box lists them with what each posts (`slash.ts`), and Enter on a name typed in full sends it. Faces are drawn as typed, never read as Markdown, wherever they turn up in a post (`faces.ts`, the first rule in `format.ts`), so the shrug keeps its arms.
- **GIFs**: the GIF button opens a sheet over the composer: trending GIFs, a search as you type, more as you scroll, and a tap posts one (`gifpicker.ts`). Searches go to Klipy through the old site's Cloudflare Worker (`GIF_PROXY` in `src/site.ts`), which keeps the Klipy key and only answers `https://ankush.one`; in dev, Vite forwards `/__gif` to it as ankush.one (`astro.config.mjs`). A GIF post carries its size, so its space is kept before it loads, and only Klipy's media host is ever shown. Empty `GIF_PROXY` turns the button off.
- **Scrolling**: the history is laid out unseen behind the Wii U wait and shown at once, already at its latest post. The feed stays pinned there as posts arrive and as pictures load, until you scroll up; new posts rise into place and the feed glides to them.
- The room keeps the last 110 posts; whoever is in it deletes older ones. Presence is rewritten every 5 seconds and shows who is typing.
- **The gate** (`src/components/live/`): before the room shows, the chat asks for your Mii (press it for a new one), a nickname and a tick against the agreement that what visitors post isn't checked first and may include swearing or NSFW material. `Gate.astro` is the screen and `gate.ts` runs it; the app decides who gets in (a taken name is refused there) and draws the Mii. The name, Mii and agreement are shared by every live app through `live/store.ts` (the old site's `irc_nick` and `irc_uuid` keys, so returning names carry over), so someone who has agreed once and kept a name walks straight in. Leaving brings the gate back with the agreement still ticked. Changing the agreement's words? Bump `AGREEMENT` in `store.ts` so everyone is asked again. Paint puts the same gate over its canvas, and the Guestbook in the sheet you sign in (`live/session.ts` runs it for both, with presence and everyone's Mii on their faces).
- To try changes without touching the real room, run a GUN relay locally and build with `PUBLIC_CHAT_RELAY=http://localhost:8765/gun`.

### Paint (`/apps/paint/`)

One shared canvas a day that everyone draws on at once (`src/components/paint/`): the app's bar with the day and its prompt in an LCD at its middle, a white tray of tools down the left (a pen, an eraser, a hand, four sizes, twelve colours, Undo and Redo), the canvas as a sheet of paper on a dotted board, and the days drawn before in a row under it with Replay and Save. On a phone the LCD drops under the bar and the tools sit along the bottom.

- **One canvas per UTC day**, 960 by 600 whatever the screen, so everyone agrees where each point is. Only today's can be drawn on; days before are read only, replayed from their strokes, and a day is only listed once someone drew on it (its first stroke links it into `apps/paint`). Each day has a prompt from the old site's list (`prompts.ts`), picked by the date. Everything is on the relay, in the old site's format, so every day drawn there still opens (`board.ts` lists the nodes).
- **Live**: a stroke goes up whole when you lift the pen, and while you draw everyone sees your pen with your Mii and name beside it, and the line it's making, through your cursor, rewritten about ten times a second. The eraser really takes strokes off, so the paper shows through.
- **Limits**: 600 strokes a day and 200 per person, after which the day is full. Undo takes back your own last stroke. Names in `CHAT_MODS` can wipe today or take a day before it down, by courtesy as in the chat.
- **Replay** draws the day again in the order it was drawn, in at most 20 seconds; **Save** downloads it as a PNG. A day opens directly at `/apps/paint/#2026-11-20`.
- **Zoom and pan** as in any drawing app (`view.ts`), from 10% up to 800%, fitted to the window until you move it: pinch (a trackpad, a touch screen, or Ctrl or Cmd with the wheel) zooms at the pointer, scrolling or two fingers pan, and so do the middle button, Space held and the Hand tool (a double click with it fits). Ctrl or Cmd with `+`, `-`, `0` and `1` zooms, fits and shows actual size, as does the zoom pill in the corner. P, E and H pick the pen, the eraser and the hand, `[` and `]` the size, Alt with a click picks the nearest colour off the canvas, and Ctrl or Cmd Z undoes, with Shift redoes. B stays the site's Back. A ring under the pointer shows the pen's size at the zoom you're at. Strokes are kept on a raster at twice the canvas's size, shown while the view moves, and drawn again as lines once it stops, so they stay sharp however close you are. On a touch screen one finger draws, and a second one landing straight after makes a pinch instead, taking back the line the first began.

### Guestbook (`/apps/guestbook/`)

Notes pinned to a green board, as Swapnote's were drawn and written (`src/components/guestbook/`), each with the paper it's on, what was written on its lines and drawn over them, and a white strip at its foot signed with its writer's Mii, where they're from, their links and the date. Notes stay paper by night; the board darkens.

- **Built in**: the board is built from the daily snapshot (`src/data/guestbook.json`), so it reads without JavaScript and survives the relay losing it; the page then adds what the relay holds that's newer. `pnpm guestbook` takes the snapshot (`scripts/guestbook.mjs`, read only towards the relay), and `.github/workflows/guestbook.yml` runs it every day, commits what changed and redeploys. It reads notes by the page's own rules (`entry.ts`), leaves out emails (a public git history can't forget one) and stops for a human when a run would add or change more than a handful at once.
- **Signing**: Sign asks for your name and the agreement first (the gate, in the sheet), then your note: draw on Swapnote's 320 by 240 paper in three inks with a pen, a marker and an eraser, write on its lines, or both, on one of five papers. Links take a handle, an address or an email and show each one's own mark (`links.ts`, from `lib/platforms.ts`); a bare `@handle` asks which platform it's on. One note per person, under your id, so signing again changes yours, and you can take it down. Someone who signed the old site keeps their note through its visitor id.
- **Moderation**: a mod's Hide hides a note for everyone at once (`apps/guestbook/hidden`), by courtesy; `src/data/guestbook-hidden.json` keeps one off the board and out of the snapshot for good. `/apps/guestbook/notes.json` is the book as built.

### Terminal (`/apps/terminal/`)

A real Linux booting as it opens (`src/components/terminal/linux.ts`): Buildroot with BusyBox, the image the old site ran, in v86 (`public/v86/`, shared with Portal), its serial console drawn by xterm.js. Everything happens as text in the terminal: the download as ASCII bars, the kernel's boot log played back line by line, then the moving-in steps, a welcome, and a prompt under your chat name. It follows the site's day and night.

- **A home to explore** (`linux-files.ts`): a README with a hint, notes, a `.plan`, a shell history to snoop on, every page of the site under `~/site`, the radio's playlist, `miisay`, a guessing game and a small text adventure in shell script, and a trail of secrets that ends in a trophy (the adventure knows the way).
- **It reaches the site**: `open`, `play`, `theme` and `music` in its `~/bin` print a private escape sequence (OSC 7777) that xterm hands to the page, which opens the page on the TV, starts the game, switches the lights or runs the radio. `upload` opens a file picker and `download <file>` saves one, both through v86's shared folder (`/mnt`); files dropped on the terminal land in `/mnt/uploads`.
- **Network**: v86's fetch backend, which makes the guest's HTTP requests from the page (upgraded to https), so sites that allow it by CORS answer (`wget http://httpbin.org/get`). `PUBLIC_LINUX_CORS_PROXY` opens that to every site through a proxy, and `PUBLIC_LINUX_RELAY` points it at a wisp server for real TCP. Neither is set.
- `poweroff`, `exit`, Ctrl+D at the prompt, or the bar's Power off shuts it down as text and goes back to the apps. Where Linux can't run, a lighter shell over the site's files stands in (`shell.ts`, files from `/apps/terminal/fs.json`), and without JavaScript the screen lists the site's folders as links.

## Games

Every game on `/games/` (`src/data/games.ts`) has a page at `/games/<id>/` (`pages/games/[game].astro`), a page on the TV like any other: a title screen (`AppCover.astro`) with the back button entries have (B presses it), the art, who made it, a green Play button and its links. Play morphs the TV into a CRT round the game (`src/scripts/play.ts`): the casing's hole, drawn as a path with the same steps either way, goes from the screen's rounded rectangle to a CRT's outline, sides bowed out and corners rounded, shaped to the game's own picture (`aspect`, 4:3 by default) and as large as fits under the TV's buttons, which stay where they always are, so there are no black bars. A dark lip runs round it like the tube's surround, the glass has a soft light and shaded edges, and the game fades in. A power button takes the plaza button's place while it plays and stops it: the game's frame is removed, which ends it and its sound, and the morph plays back to the ordinary TV. Leaving the page while playing puts the TV back at once. The game runs in a frame of its own, named by its full `index.html` path (the dev server serves no folder's index), so its keys, pointer lock and sound stay inside it and the site's B and M keep working outside it.

- **Your games** point at their project (`project`), which gives the cover, description and links. Those built for the web on itch.io play through itch's embed, letterboxed to their shape (`aspect`). Lucky Knight's build needs cross-origin isolation, which no framed page gets, so its Play opens itch.io in a new tab (`newTab`).
- **Everyone else's** run from files served by this site, under `public/play/`, so nothing breaks if another site goes: DOOM (Chocolate Doom in WebAssembly with the shareware WAD), Quake III Arena (James Darpinian's ioquake3 WebAssembly build, GPLv2, with the demo's `pak0.pk3` split into three parts under 25 MiB that the page joins; only multiplayer still uses his peer server), Portal (the Still Alive floppy demo on v86, which it shares with the Terminal from `public/v86/`), the Flash games (Ruffle, `public/play/flash/?game=<name>`) and Crysis (a joke: it never loads). Their art is `src/assets/games/<id>.webp`: the game's real icon centered on a blurred copy of itself, opaque square icons cut to a squircle.
- `public/play/` is excluded from `astro check` (`tsconfig.json`), since it is other people's built code.

## Home page plaza

The home page is a Wii U style plaza rendered with three.js, timed off the console's own start up. It opens on your Mii floating in the haze with a tap prompt over it. The click (browsers only allow sound after one) starts the music and the opening: you fall under real gravity, the camera riding down with you, to your friends waiting below, land with a knee bend and wave hello while they clap, the camera pulls back as ten glass blocks tumble in one after another, then a crowd runs in with their hands up and gathers under the blocks. Your friends stand round you in a loose, uneven group that is scattered afresh on every visit, and now and then one wanders a few steps to another place in it (`scatter` and `drift` in `plaza/crowd.ts`). Now and then someone in the crowd says something real from the site in a speech bubble.

- **The lobby** (`plaza/Lobby.astro`) is for visitors who would rather not play: your name and the site's sections (`LOBBY_NAV` in `src/site.ts`, which is `NAV` plus links marked `wide` that show on big screens only) as quiet text beside your floating Mii, a column on the left on a big screen and a row across the top on a phone, level with the switches. They are plain links: the lobby sits outside the plaza, so pressing one never starts the opening or the sound. It shows while the plaza loads and waits for its click and fades as the opening begins; a plaza that comes up settled (`/#0`, reduced motion) never shows it for long. It is also the page's visible `h1` and menu for crawlers.
- Each block shows title art from `public/plaza/icons/<section>.webp` (512px, named after the section's path, e.g. `blogs.webp`), drawn like the Wii U's own system icons so the set reads as one family: one bold object specific to the section, in flat solid color with a chunky darker side face for depth, lit from the top left, on pearly white, with no text, gloss, glow, drawn tile or floating decoration (the glass block is the frame). The block's name shows on a tag when it is hovered or focused. A section without a file falls back to a drawn glyph with its name.
- The back row has `FEATURED` feature blocks that turn once round to a new random pick every 6.9 seconds (`FEATURE_EVERY` in `main.ts`), the picture changing as the block passes edge on (`flip` in `cubes.ts`). Picks are the site's real things, as the bubbles are: entries with a cover (the cover is the art), other people's games on `/games/` (your own are projects already), and apps with block art in `public/plaza/icons/` that aren't a block already. Once the plaza is up, a few drawings from Paint join them, the first one next in line (`plaza/sketch.ts`): random days someone drew on (a few strokes at least, never one a mod took down), drawn on white paper and cropped square round what was drawn, named by the day's prompt and opening that day in Paint. Pages that only explain the site (Contact, Privacy and the like) are left out. Each kind (blog covers, project covers, timeline covers, games, apps, Paint) gets an equal share of turns however many it has, and within a kind everything shows once before anything repeats (`plaza/rotation.ts`). A block you're pointing at or holding waits for the next turn.
- Which links become blocks, their glyph and colors, your Mii (`ME`), your friends (`HERO`) and the crowd size live in `src/data/plaza.ts`. Block names come from `NAV` and `FOOTER_NAV`.
- Your Mii speaks first on every visit, a moment after the camera has pulled back, a greeting picked at random from `WELCOME` in `src/data/plaza.ts` (plain, punny, unhinged, and game references), alone until it ends. One of them is true: the Konami code on the plaza sets the whole crowd dancing.
- Bubbles are every entry on the site (blog posts, projects, the timeline), built at build time in `src/lib/plaza.ts` and each said by someone near its section's block, with Paint's drawings said under the Apps block. A drawing (a Paint day on its white paper, cropped 16:10 round what was drawn, or a chat drawing's ink on the glass, as the chat shows it) fills the bubble in place of text, as Miiverse showed them. Pages that only explain the site (Contact, Privacy and the like) are left out. Each kind (blog posts, projects, the timeline, chat, Paint) gets an equal share of turns however many it has, never the same kind twice running, in a new order on every visit (`plaza/rotation.ts`). Up to four are up at once on a desktop, a new one every couple of seconds to fill them, and one at a time on a phone (`MOST` in `plaza/bubbles.ts`).
- The chat joins in once the plaza is up (`plaza/chatter.ts`): a random few of the room's latest messages and drawings are said under the Chat block, the sender's name on the tag and their Mii (with the feeling they posted with) as the icon, and pressing one opens the chat. Messages the visitor hasn't seen go first, newest first, right after the greeting, as does anything said while they are on the plaza. "Seen" is the newest message shown in the chat or said on the plaza, kept in `localStorage` (`chat_seen`, `chat/store.ts`); without it, anything from the last day counts as new, and your own messages never do.
- The runtime is in `src/components/plaza/`:
  - `layout.ts` holds the camera and where everything stands. The numbers were measured off captures of the console and are stored as screen positions, so wide and tall windows both work.
  - `floor.ts` draws the tiled floor, its glare and the mirrored Miis. `cubes.ts` draws the glass blocks: thin squircle slabs that refract a copy of the scene behind them, made each frame in `main.ts`. `icons.ts` draws the picture inside each one.
  - `heads.ts` draws distant heads as flat pictures, all in one draw call, photographed from twelve angles once each head is built, each photograph with a picture of its depth so every pixel sits as deep as the head it shows (long hair goes behind the shoulders, not over the body); heads near the camera stay real 3D.
  - `crowd.ts` decides where every Mii goes and what it does. `motion.ts` is the library of moves: walk, run, clap, wave and so on.
  - `main.ts` plays the opening and handles zoom, links and sound.
- Zoom is smooth and continuous: mouse wheel, trackpad or touch pinch, or the `+` and `-` keys. It starts at the farthest view. The camera drifts a little toward the mouse, every block turns a little to face it, and a hovered block leans in further. Drag a block to spin it, as far round as you like; let go and it springs back to rest. A drag never counts as a click. Touch does the same: tap to open, drag a block to spin it, drag on open floor to look around, pinch to zoom.
- Miis can be played with once the opening is over. Tap one and it turns to you and does something (a wave, a dance, a faint...); keep tapping and it loses its temper. Press and drag to pick it up by the shirt: it dangles from the pointer, swinging as you move. Let go to set it down, or flick to throw it. Wherever it lands it freezes for a second, looks round in shock and runs off (your friends run back to their places). A held finger also lifts a Mii on touch screens. On a desktop, resting the pointer on a named Mii shows its name over its head on a square see-through tag in a pixel font, as name tags are in Minecraft. The tag has a size in the world (`TAG_SIZE` in `main.ts`), so it grows and shrinks with the Mii at every zoom, holding at a readable minimum far out. The font is Monocraft (SIL Open Font License, `public/fonts/`), cut down to Latin letters. Crowd Miis only get their full set of faces (`MiiSet.liven`) once someone plays with them, which keeps memory down.
- The sound is one recording, `public/media/warawara-plaza.mp3`, cut so the chime lands on your drop, the footsteps on the crowd's run in, and the theme loops from then on. `SCORE` in `audio.ts` holds those moments, and while the recording runs through them it is the scene's clock, so the two cannot drift.
- Sound plays from the click that starts the opening; Enter or Space works too. Once the crowd is in, the theme hands over to the radio (see Music). `M` mutes and unmutes.
- The opening plays on every load. The first time in a browser session it can't be skipped; after that, Escape or another click skips it. The TV's plaza button opens `/#0`, which skips it altogether: the plaza starts settled, everyone already there, and takes the `#0` off the address so a refresh plays the opening as usual. Going back to it in history does the same. Reduced motion skips the wait and the opening and stills the crowd.
- Without WebGL or JavaScript, or with Save-Data on, the plaza is only its haze and the lobby is the page, with your portrait in the middle.
- If frames run slow, the plaza lowers its resolution a step at a time, and raises it again when there is room. Its heaviest files start downloading with the page.
- In `pnpm dev`, `__plaza.seek(4.2)` in the browser console jumps to a moment of the opening and holds it, `__plaza.zoom(2.5)` sets the zoom (0 to 3), `__plaza.point(x, y)` places the pointer, `__plaza.mii(i)` says where Mii `i` is on screen, `__plaza.look(i)` holds the camera up close on it (`__plaza.look()` lets go), `__plaza.camera()` says where the camera is (step `seek` a frame at a time to check a move for jumps) and `__plaza.play()` resumes.

## Miis

Miis are real Wii U Miis, drawn by Nintendo's face library (FFL, compiled to WebAssembly through [FFL.js](https://github.com/ariankordi/FFL.js)) on the Wii U body models. The code in `src/components/mii/` comes from the [Mii Creator](https://github.com/ankushKun/mii-creator) fork.

- To add Miis, drop Mii QR code images into `src/data/miis/`. QR codes from a 3DS, a Wii U, Miitomo or Tomodachi Life all work, and so do the ones shared online. The build decodes them (`src/lib/miis.ts`) and every one joins the crowd, shuffled on each visit so different faces stand next to you. A Mii is named after its file (`Steve Jobs.png` is Steve Jobs). Random Miis from the Mii Maker's own generator fill the rest.
- `ME` and `HERO` take a file name from that folder or a Mii code (base64 of the 96 Mii bytes).
- What a QR code can't carry goes in `LOOKS` in `src/data/plaza.ts`, by file name (`MiiLook` in `plaza/types.ts`). `parts` change the Mii by FFL's CharInfo names (`hair: { type: 29, color: 31 }`); colors of hair, eyes, eyebrows, mouth, beard and glasses are the Switch's hundred (0 to 99; a QR code only holds a few), which FFL draws when the Mii is turned into a CharInfo on the spot (`withParts` in `mii/rig.ts`), on the plaza and in the `/mii/` shuffle. `headset` (its lights' color) and `ponytail` (its color) are drawn on (`plaza/headgear.ts`), for the DJ, their dancers and the middle group only, since far-off crowd heads are flat pictures. Miku's teal and Gumi's green are set there, and `BACKUP` makes new Miis the same way from one to start from.
- `/mii/` loads a QR code image (open, paste or drop) or a code, shows the Mii in 3D and gives you its code.
- `data.ts` reads and writes Mii data and decrypts QR codes. It has no DOM or three.js, so the build and the browser share it.
- `rig.ts` draws a group of Miis: one FFL head per Mii, and every body of one gender in a single skinned draw call. A pose is a plain object of joint angles. The crowd and `/mii/` both use it.
- `public/ffl/` holds the FFL WebAssembly build, its resource file and the Wii U bodies, about 5.6 MB that the plaza loads on first visit.

## SEO, AEO and GEO

Every page gets a canonical URL, a meta description, Open Graph and Twitter tags with a 1200x630 image, and a JSON-LD graph that ties it to the `WebSite` and `Person` nodes: `BlogPosting` for posts, `CreativeWork` for projects, `Article` for timeline entries, `ProfilePage` for About, `ContactPage` for Contact, `CollectionPage` for indexes, and breadcrumbs everywhere. The sitemap picks up new pages automatically.
